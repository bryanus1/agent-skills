# Turborepo and pnpm Workspaces

---

## 1. pnpm Workspaces

```yaml
# pnpm-workspace.yaml
packages:
  - "apps/*"
  - "packages/*"
  - "services/*"   # optional, when there are polyglot services
```

- **Internal dependencies:** always with the `workspace:*` protocol.
  ```bash
  pnpm --filter web add @acme/contracts@workspace:*
  pnpm --filter mobile add @acme/design-tokens@workspace:*
  ```
- **External dependencies:** add them to the workspace that uses them (`pnpm --filter api add @nestjs/swagger`, `pnpm --filter mobile add expo-secure-store`), not to the root. The root only carries global tooling (`turbo`, `typescript`, `oxlint`, `oxfmt`).
- **pnpm version:** `packageManager` in the root `package.json` pins it (`Corepack` and `Turborepo 2` require it). `engine-strict=true` in `.npmrc` enforces `engines.node`.
- **postinstall scripts in pnpm 10:** pnpm 10 blocks dependencies' `postinstall` scripts by default (`esbuild`, `sharp`, `@prisma/client`). If an app needs them, approve them with `pnpm approve-builds` after confirming with the user.

### Special Considerations for Expo / React Native (`apps/mobile`)

Metro and pnpm require avoiding duplicate copies of `react` / `react-native` and enabling `exports` resolution:

1. **`.npmrc` at the root** (generated automatically by `scaffold-monorepo.mjs --apps ...,mobile`):
   ```ini
   engine-strict=true
   public-hoist-pattern[]=*react*
   public-hoist-pattern[]=*expo*
   ```
2. **`apps/mobile/metro.config.js`** (generated by `scaffold-app.mjs mobile --type mobile`):
   - `config.watchFolders = [monorepoRoot]` to watch changes in `packages/*/dist`.
   - `config.resolver.nodeModulesPaths` pointing to both `apps/mobile/node_modules` and `<root>/node_modules`.
   - `config.resolver.unstable_enablePackageExports = true` to honor the `exports` of `@acme/contracts`, `@acme/api-client` and `@acme/design-tokens`.

## 2. Turborepo Pipeline

```json
{
  "$schema": "https://turbo.build/schema.json",
  "tasks": {
    "build": {
      "dependsOn": ["^build"],
      "env": ["NEXT_PUBLIC_API_URL", "EXPO_PUBLIC_API_URL", "PUBLIC_API_URL", "PUBLIC_SITE_URL"],
      "outputs": ["dist/**", ".next/**", "!.next/cache/**", ".astro/**", ".expo/**"]
    },
    "dev": { "dependsOn": ["^build"], "cache": false, "persistent": true },
    "lint": { "dependsOn": ["^build"] },
    "format:check": {},
    "typecheck": { "dependsOn": ["^build"] },
    "test": { "dependsOn": ["^build"], "outputs": ["coverage/**"] }
  }
}
```

- **`^build`:** compiles the internal packages into `dist/` before running the consumers' `build`, `lint`, `typecheck` or `test`.
- **`outputs`:** includes `.next/**` (Next.js), `dist/**` (packages, NestJS, Astro, Vite, Worker) and `.expo/**` (Expo).
- **OXC in Turborepo:** `oxlint` and `oxfmt` run in milliseconds per workspace; `lint` depends on `^build` so the compiled types of `packages/*` are ready when validating imports.
- **`dev`:** runs `^build` first. If you edit internal packages in parallel while running Next.js, Astro or Expo, also run their watch (`pnpm --filter @acme/contracts dev`).

## 3. Useful Filters

```bash
pnpm turbo run build --filter web                  # Next.js web only
pnpm turbo run build --filter landing...           # the Astro landing and its internal dependencies
pnpm turbo run typecheck --filter mobile...        # Expo mobile and its packages
pnpm turbo run test --filter ...@acme/contracts    # contracts and every app that depends on it
pnpm turbo run lint --filter '[origin/main]'       # only workspaces changed relative to main
```

## 4. Environment Variables per Platform

| App | Public prefix (client) | Local file | Rule in `turbo.json` |
| :--- | :--- | :--- | :--- |
| `apps/web` (Next.js) | `NEXT_PUBLIC_*` | `apps/web/.env.local` | Declare in `tasks.build.env` |
| `apps/mobile` (Expo) | `EXPO_PUBLIC_*` | `apps/mobile/.env` | Declare in `tasks.build.env` |
| `apps/landing` (Astro) | `PUBLIC_*` | `apps/landing/.env` | Declare in `tasks.build.env` |
| `apps/admin` (Vite SPA) | `VITE_*` | `apps/admin/.env` | Declare in `tasks.build.env` |
| `apps/api` / `worker` | No public prefix | `apps/api/.env` | Secrets stay on the server, never in `packages/` |

## 5. Common Problems

| Symptom | Cause | Solution |
| :--- | :--- | :--- |
| `Cannot find module '@acme/contracts/invoices'` | Package not built, or a missing `exports` entry | `pnpm turbo run build --filter @acme/contracts` and check `exports` |
| Metro (Expo) does not resolve `@acme/contracts/invoices` | Missing `watchFolders` or `unstable_enablePackageExports` | Regenerate `apps/mobile/metro.config.js` with `scaffold-app.mjs` |
| `Invalid hook call` in Expo inside the monorepo | There are two copies of `react` in `node_modules` | Add `public-hoist-pattern[]=*react*` to `.npmrc` and reinstall |
| Astro fails when importing an internal package in SSR | `exports` points to `src/`, or Vite needs pre-bundling | Compile to `dist/` and keep standard `exports` (`types` + `default`) |
| The API fails resolving subpaths | The API's `tsconfig` uses `moduleResolution: node10` | Extend `@acme/tsconfig/nestjs.json` (`Node16`) |
| Cache returns stale results | `outputs` or `env` missing in `turbo.json` | Declare them and run `turbo run <task> --force` once |
